# Local-to-public Live AI engineering backlog

**Separate milestone; no public activation or provider call is authorized.** Current implementation is loopback-only, disabled by default: `sandbox/__main__.py` binds `127.0.0.1`; `sandbox/app.py` accepts loopback Host/Origin and sets a non-Secure local cookie; `sandbox/service.py` reserves four local turns in SQLite and fixes SC-01/Ollama; `ProviderAdapter` has a per-run maximum. These are useful local controls, not public hosting, distributed budget, or protected-effect isolation. The static eight-file release does not include this backend.

| Order | Engineering task | Done only when |
| --- | --- | --- |
| 0. Public topology and authority | Choose separately approved host, account, region and data flow; define no-effect deployment unit with **no** canonical protected DB, writer credential, API-108/API-109 route, mount or network path. Produce a threat diagram and negative capability tests proving the public process cannot reach protected state. Do not proxy the local CLI unchanged. |
| 1. Provider and rights gate | Verify exact account/organization, model, free/paid terms, synthetic prompt and public-output rights, privacy/retention and tool semantics from provider-controlled evidence. Store a replacement credential only in server-side secret storage; prove browser bundles, logs and traces contain no key. No key or provider request is needed for this backlog. |
| 2. Approved budget ledger | Owner approves a **nonzero** spend/request ceiling and billing cutoff. Implement one atomic distributed reservation ledger for requests/tokens/currency, with per-run, per-visitor and global caps that survive multiple instances and crashes. Exhaustion fails closed **before** a provider dispatch; failed/time-out dispatches remain charged/uncertain until reconciled. Race, restart and partition tests must show no over-admission. |
| 3. Visitor isolation and abuse | Replace local Host/Origin assumptions with public HTTPS-only session/cookie policy, CSRF, trusted proxy configuration and per-visitor evidence ownership. Add distributed IP/session rate controls, bounded synthetic inputs, retention/deletion and abuse monitoring. Cross-session, forged header, replay, flood and malicious-prompt tests must not disclose another visitor's trace or bypass quota. |
| 4. Failure semantics and kill switch | Add durable run state for timeout, canceled request, lost response and process death; distinguish dispatch attempt from model processing and from known provider usage. An operator kill switch must stop admission across all instances, preserve uncertain charges and be exercised during in-flight tests. No automatic fallback to another provider or new request ID. |
| 5. Evidence and operations | Store minimal redacted tool-call/observation/continuation provenance with explicit `LIVE` classification; never turn model prose into effect evidence. Monitor spend, 429/5xx, latency, queue depth and unknown outcomes without secrets. Document on-call ownership, credential revocation, rollback, state migration and trace deletion. Exercise rollback without re-enabling admissions. |
| 6. Public acceptance gate | Run isolated synthetic end-to-end A and B with real scoped read observations only after a new inference authorization; prove no protected effects, concurrent quota safety, session isolation, abuse resistance and cost containment. Obtain an explicit, separate public Live deployment approval naming build, host, provider, model and spend cap. |

The existing mock-SDK local tests in `tests/unit/test_local_live_gate.py` cover a four-turn A/B shape, failure-count uncertainty and no-effect tables; they do **not** satisfy any public deployment gate above. The known coherent-rollback xfail blocks protected actions independently.
