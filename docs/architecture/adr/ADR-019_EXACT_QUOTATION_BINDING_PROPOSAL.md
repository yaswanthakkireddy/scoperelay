# ADR-019 (APPROVED) — Exact quotation binding for Agent A

**Status: APPROVED for Task 07E offline implementation by the user's explicit 2026-10-14 decision.** No live inference, protected effect, recovery activation or deployment was authorized. The tracked `docs/architecture/S5_CANONICAL_ARCHITECTURE.md` resolves the former filename concern; this ADR is consistent with its §§5–8, 10–11 trust boundaries. Canonical API/data/agent/policy contracts were updated within this approval. Offline verification does not establish real A→B success or perfect intent recognition.

## Decision

Use a versioned Agent A intermediate format in which A selects *exact quotations* from its one scoped `read_assigned_ticket` observation and trusted code derives code-point spans **only for unambiguous exact occurrences**. Prefer this over model-computed offsets. The user's approval covers the V2 interface, deterministic binding, distinct raw/derived evidence, episode pinning, conservative relevance, historical compatibility and unchanged read tool.

## Evidence and problem

Task 07C.2's actual A model cited `ORD-101` at `[16:31)` although the exact stored source has it at `[56:63)`; trusted `resolve_span` rejected it. In Task 07C.3 a second actual A tool call/continuation again failed `SourceReferenceError: excerpt does not match source span`; that run did not retain exact erroneous offsets. Its separate isolated B success is not an A→B success. Both runs left protected effects untouched. See the two Task 07C reports for trace IDs and limits. The provider's internal cause is unknown. Another prompt-only revision cannot establish a dependable arithmetic guarantee, especially for Unicode, repeated strings and source changes.

## Existing boundary

`API_CONTRACTS.md` §E fixes the A tool's model-facing fields and historical model-authored `CandidateRequestV1` with `source_spans`. `DATA_MODEL.md` DM-011/013–015 and §§E–F require an immutable ticket source, actual tool event, exact UTF-8 digest and Python code-point `[start,end)`/excerpt equality. `POL-014` forbids inventing or repairing invalid citations from model testimony. `PRD-SEC005/011/018/020` require separated handoff provenance, sole protected writer, independently resolved source and genuine model/tool evidence. The existing V1 validator remains unchanged for historical episodes.

## Proposed protocol (one versioned path, no fallback repair)

1. A still makes its genuine, sole `read_assigned_ticket({"ticket_id":...})` call; its **fixed tool payload remains unchanged**. The dispatcher persists the actual successful `DM-014` event, scoped episode/invocation/ticket, returned source ID/version/digest and body, and actual post-tool A continuation.
2. In the new, explicitly selected `CandidateInterpretationV2` response (strict `extra=forbid`), A authors the existing non-authoritative interpretation fields and `source_quotes` (1–8). Each quote has only `source_id: str`, `source_version: int`, `source_digest: lowercase SHA-256 hex`, `quotation: nonempty exact Unicode string <=1024 code points`. The response has `candidate_id` (untrusted suggestion), `ticket_id`, `operation_hint`, `order_ref_text`, `requested_recipient_text`, `content_class_hint`, `uncertainty`, and `other_candidates` with the existing bounds; it has **no** `start`, `end`, `approved_by`, recipient ID, grant, tool-event override, SQL or protected tool. `REFUSED`/`UNABLE` remain separate failure branches. A selects the passage and interpretation; it does not supply source location or authority.
3. A trusted binder accepts the raw V2 output **only from that invocation's actual continuation** and fetches the successful A observation and the exact immutable DM-011 row by server-owned episode/ticket/source scope. It checks event role/owner/tool name, call ID and delivery ordering; source ID/version/digest, ticket, episode source version/current-state eligibility, and SHA-256 of unchanged original `body_text`. Model-echoed identity fields are comparisons only. Never trust a client/model-supplied observation object.
4. For each quotation, locate exact Python-string occurrences with no Unicode normalization, case folding, whitespace repair, fuzzy search, stemming or nearest match. Require **exactly one occurrence**, including overlapping matches; zero or multiple means `SOURCE_QUOTE_UNRESOLVED` and no valid candidate. Derive `[start,end)` from that occurrence, re-run the current `resolve_span`, and reject empty/oversized quotes. A model may select a longer unique quote if the shorter one repeats, but there is no silent automatic expansion.
5. Independently test that the selected passage actually supports the selected hypothesis (at minimum the exact selected order reference occurs as a delimited token in a routine quote; reject valid but irrelevant greetings/wrong-order quotes). This is a *necessary support check*, not a proof of active human intent. Quoted/fake SYSTEM or MANAGER language remains `CUSTOMER_UNTRUSTED`; if active-vs-quoted meaning cannot be established conservatively, stop/clarify. Existing ownership, recipient, grant and policy verification still occurs through `API-102/103`. No citation alone yields `ALLOW`.
6. Create a **server-compiled** `CandidateRequestV1` only after all quote/source/support checks pass; replace model `candidate_id` server-side. Preserve the exact raw V2 selection and quote→span binding map separately with provenance labels and failure details. Never claim the derived numeric offsets were model-authored. A failed V1 span remains a failed V1 span; there is no automatic conversion/retry of an old invalid answer. H3 labels A's interpretation and server compilation separately; H4 contains checked source refs. H1/H2 are reconstructed independently and B cannot use H3/H4 as authority.

The binder's success means *exact text presence in a particular source snapshot*. It does not establish actual customer intent, verified order ownership, manager/supervisor consent, disclosure safety or permission to commit. `API-108/109`, approval, business key, resource outcome, rollback and queue writer are out of scope and unchanged.

Every new audit field is non-authoritative except transport/source provenance established by the trusted dispatcher/repository. Source text and raw model content remain lower-trust synthetic restricted data. The audit view must escape it and avoid private reasoning or secrets.

## Failures and migration

Wrong/missing source or tool event, stale source version, digest mismatch, zero/multiple quote occurrences, irrelevant passage, wrong order reference, malformed/extra fields, uncertain active intent, or failed actual continuation: record a bounded diagnostic, leave A `FAILED` or a truthful non-success decision as appropriate, create **no completed valid candidate/handoff/B continuation/protected attempt**. Do not turn model failure into `EXPLICIT_POLICY_DENIAL` or silently change source text. Historical V1 episodes and traces retain their original failures. Forward migration applies to new version-pinned episodes without rewriting old evidence; rollback means turning off V2 for **future** episodes through reviewed code/config change while retaining labeled historical V2 evidence.

## Verification required before implementation acceptance

Use immutable synthetic sources to cover unique/repeated and overlapping quotes, Unicode emoji/combining code points, wrong or stale version/digest, no normalization or fuzzy rescue, partial/empty quotes, cross-ticket/episode/invocation event reuse, wrong order/irrelevant but valid quote, fake SYSTEM and quoted approval, extra authority fields, changed source after read, failure before candidate persistence, H1/H2 independence, H3/H4 labeling, oracle isolation, no protected state change, and real A/B tool continuation under a **separate** future live authorization. The `tests/experimental/test_source_quote_binding_07d.py` harness proves only deterministic local binding/rejection; it is not integrated into the production path.

It permits the V2 output/interface, DM-015 authorship correction plus separate audit record/migration, episode protocol pinning, and conservative support rule, but **not** live inference or protected effects.
